# 7장. 분산 시스템을 위한 유일 ID 생성기 설계

> **책**: 가상 면접 사례로 배우는 대규모 시스템 설계 기초  
> **읽은 날짜**: 2026-11-03  
> **작성자**: @xrtro23

## 한 줄 요약
분산 시스템에서는 일반적인 auto_increment 속성을 사용 불가로, 여러 서버에서 유일한 ID를 생성하는 방법이 필요하다. 
다중 마스터 복제, UUID, 티켓 서버, 스노플레이크 접근법 등이 있으며, 각 방법의 장단점을 고려하여 시스템에 적합한 방식을 사용하자.

## 핵심 내용

### 분산 시스템에서 유일 ID 생성
- 일반적인 auto_increment 속성 사용 불가, 분산 환경은 적용x
- Why? : 해당 접근법은 불가, DB 서버 한대로는 감당 불가, 여러 DB 사용시 지연 시간 낮추기 힘듬

### 1) 다중 마스터 복제
auto_increment 기능을 활용하지만 1만큼 증가가 아닌 서버 수만큼 증가

**장점**
- 규모 확장성 문제를 쉽게 해결
- 초당 생산 가능 ID수 늘릴수 있다

**단점**
- 여러 데이터 센터에 걸쳐 규모를 늘리기 어려움
- ID 유일성은 보장되나 시간 흐름에 맞추어서 커지도록 보장할 수 없다
- 서버 추가/삭제 시 동작이 매끄럽지 않음

### 2) UUID
유일성이 보장되는 ID를 만드는 방법으로 컴퓨터 시스템에 저장되는 정보를 식별하기 위한 128비트짜리 수로 구성된다.

**장점**
- UUID 값은 충돌 가능성이 낮고 만드는 것이 단순하다
- 서버 사이의 조율이 필요 없어 동기화 이슈가 없다
- 각 서버가 자기가 쓸 ID를 알아서 만드는 구조로 규모 확장이 쉽다

**단점**
- ID가 128 비트로 길어 ID의 비트 제한이 있는 경우 비적합하다
- ID를 시간순으로 정렬 불가
- 숫자가 아닌 값이 포함될수 있다

### 3) 티켓 서버
유일성이 보장되는 ID를 만들어 내는데 쓰이고, 분산 기본 키를 만들어 내기 위해 사용
auto_increment 기능을 갖춘 DB인 티켓 서버를 중앙 집중형으로 하나만 사용하는 구조다

**장점**
- 유일성이 보장되는 오직 숫자로만 구성된 ID를 쉽게 생성
- 구현이 쉽고 중소 규모 애플리케이션에 적합

**단점**
- 티켓 서버가 SPOF 되어 이 서버에 장애 발생시 모든 시스템이 영향을 받는다
- 위 문제를 방지하려 여러 티켓 서버 운영시 데이터 동기화 문제 발생

### 4) 스노플레이크 접근법 (트위터 예시)
바로 ID 생성이 아닌 생성할 ID의 구조를 여러 섹션으로 분할해서 ID 생성
사인 비트, 타임스탬프, 데이터센터 ID, 서버 ID, 일련 번호로 구성된다.

**구성 요소**
| 구분 | 설명 |
|---|---|
| 사인 | 음수/양수 구분 (지금은 큰 쓰임새가 지금은 없음) |
| 타임스탬프 | 시간 경과 표시 |
| 데이터센터 ID | 2^비트수 ex) 2^5 = 32 |
| 서버 ID | 위와 동일 |
| 일련 번호 | 각 서버에서 ID 생성마다 일련번호 1 증가, 1ms 경과시 0으로 초기화 됨. |

**64 비트 예시**
| 구분 | 비트 수 |
|---|---|
| 사인비트 | 1비트 |
| 타임스탬프 | 41비트 |
| 데이터센터 ID | 5비트 |
| 서버 ID | 5비트 |
| 일련번호 | 12비트 |

**각 절의 길이 최적화**
ex) 동시성이 낮고 수명이 긴 애플리케이션이면 일련번호 절의 길이를 줄이고 타임스탬프 절의 길이를 늘리는것이 효과적

## 면접 예상 질문
1. **Q. 분산 시스템에서 일반적인 auto_increment를 사용하기 어려운 이유는 무엇인가요?**  
   **A.** 여러 서버에서 각 ID를 생성하면 중복될 수 있고, 하나의 DB에서 관리하는건 감당이 불가능 하며 이를 해결하기 위해 여러 DB 사용시에는 지연시간 등 다른 문제가 발생함.
2. **Q. UUID의 장단점은 무엇인가요?**  
   **A.** 서버 간 조율 없이 각 서버에서 ID를 쉽게 생성 가능하지만, 비트가 128로 길어 제한된 환경에서는 비적합하고 ID를 시간순으로 정렬이 불가능하다.
3. **Q. 티켓 서버 방식이란 무엇인가요?**  
   **A.** 중앙 서버에서 auto_increment를 이용해 유일한 ID를 생성하는 방식으로 구현하기 쉽지만, SPOF가 되어 중앙 서버에 장애가 발생하면 모든 시스템이 영향을 받아 ID 생성이 불가능하다
4. **Q. 스노플레이크 접근법이란 무엇인가요?**  
   **A.** ID를 시간, 데이터센터, 서버, 일련번호 등으로 여러 섹션을 나누어 생성하는 방식으로 여러 서버에서 중복 없이 ID를 생성할 수 있고 타임스탬프가 시간의 흐름에 따라 큰 값을 가지기 때문에 시간순으로 정렬하기 쉽다
5. **Q. 다중 마스터 복제와 스노플레이크 접근법의 차이점은 무엇인가요?**  
   **A.** 다중 마스터 복제는 서버마다 ID를 일정한 간격으로 증가시키는 방식이고, 스노플레이크는 시간과 서버 정보 등을 조합해 ID를 생성하는 방식입니다.
