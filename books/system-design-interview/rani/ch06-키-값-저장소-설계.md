## 한 줄 요약
키-값 저장소는 데이터를 "키-값"의 쌍 형태로 관리하는 비관계형 데이터베이스로, 단일 서버 키-값 저장소 구조를 개선한 분산 키-값 저장소의 기능이 있다.
주로 대규모 환경에서는 안정 해시를 통한 데이터 분산을 하며 데이터 다중화와 일관성, 장애 처리 등을 활용하여 높은 일관성과 가용성을 확보한다.
* 파티션 문제는 필수

## 핵심 내용

### 키-값 저장소

키-값 저장소 : 키-값 데이터베이스 (비 관계형 데이터베이스)
- 고유 식별자를 키로 가져야 함 // 이런 연결이 키-값 쌍
- 값은 형태가 정해지지 않음 ex) 문자열, list, 객체 등등

| 기능 | 설명 |
| --- | --- |
| put | 키-값을 저장 // key + value |
| get | 해당 인자의 값을 꺼냄 // key |

### 단일 서버 키-값 저장소
1대 서버만 사용
- 키-값 쌍 전체를 메모리에 해시 테이블로 저장

**장점**
- 빠른 속도

**단점**
- 모든 데이터를 메모리 안에 두는게 불가능

**개선방법**
- 데이터 압축 or 디스크에 저장 (자주 쓰는 데이터 제외하고)

### 분산 키-값 저장소
분산 해시 테이블
- 키-값 쌍을 여러 서버에 분산

### CAP 정리
세 요구사항을 동시에 만족하는 분산 시스템 설계 불가능
두가지를 충족하면 한가지를 포기해야 한다

**CAP의 세 가지 요소**
(분산 시스템에 접속하는 클라이언트는)
| 구분 | 설명 |
| --- | --- |
| C : 일관성 (consistency) | 어디를 보든 같은 데이터를 본다 |
| A : 가용성 (availability) | 장개가 발생해도 항상 응답을 받는다 |
| P : 파티션 감내 (partition tolerance) | 파티션이 생겨도 시스템은 계속 동작함 |

**파티션**
- 두 노드 사이에 통신 장애가 발생

**분산 시스템 종류**

| 종류 | 특징 |
| --- | --- |
| CP 시스템 | 가용성을 희생 |
| AP 시스템 | 데이터 일관성을 희생 |
| CA 시스템 | 파티션 감내는 지원 X |

But 통상 네트워크 장애는 피할수 없는 일이기에, 파티션 문제를 무조건 감내할수 있게 설계해야 하므로 실제로는 CA 시스템은 존재하지 않는다

**예시)** 분산 시스템에서 데이터는 여러 노드에 복제되며, 각 노드에 보관하는 상황

a) 이상적 상태 : 파티션 X, 데이터 일관성 및 가용성 만족
b) 실세계의 분산시스템 : 분산시스템은 파티션 문제를 피할수 없으므로 통신 장애가 일어남

- if CP : 일관성 선택 - 데이터 불일치 문제로 인해 문제가 해결될때까지 오류 반환
- if AP : 가용성 선택 - 낡은 데이터 일지라도 읽기 연산 허용 파티션 문제 해결 후 새 데이터 전송

### 시스템 컴포넌트 및 기술

#### 1) 데이터 파티션
- 대규모 애플리케이션에서 전체 데이터를 한 서버에 넣는건 불가능
- 데이터를 작은 파티션으로 분할해 여러 서버에 저장
- 고르게 분산 + 노드 변경(추가/삭제) 시 데이터 이동 최소화가 중요
- 안정해시 방법 사용 → 장점 : 규모 확장 자동화 및 다양성

**규모 확장 자동화**
- 시스템 부하에 따라 서버가 자동으로 추가되거나 삭제

**다양성**
- 각 서버의 용량에 맞게 가상노드의 수를 조정 ex) 고성능 서버는 많은 가상 노드를 가지도록

#### 2) 데이터 다중화
- 높은 가용성과 안정성 확보를 위해 데이터를 N개 (튜닝 가능한 값) 서버에 비동기적으로 다중화 해야함.
- key 를 해시링 위에 배치하여 처음 만나는 N개 서버에 데이터 사본을 보관하는 당식

**문제점**
But. 가상노드 사용시 N개 노드가 대응될 실제 물리서버의 개수가 N보다 작아질수 있음

**개선방법**
- 노드 선택할 때 같은 물리 서버를 중복 선택하지 않게 해야하고,
- 정전이나 네트워크 등 여러 이슈를 방지하기 위해 다른 데이터 센터에 보관이나 고속 네트워크 연결을 해야함.

#### 3) 일관성
- 여러 노드에 다중화된 데이터는 적절히 동기화가 되어야 함.
- 정족수 합의 프로토콜을 사용하여 읽기/쓰기 연산 일관성 보장
- N, W, R 3가지 변수를 조절해 일관성과 가용성의 균형을 맞춘다

**N, W, R**
| 구분 | 설명 |
| --- | --- |
| N | 사본 개수 (데이터 복제해 저장하는 전체 노드의 수) |
| W | 쓰기 연산에 대한 정족수 (쓰기 연산이 성공한 것으로 간주되는 응답을 받아야 하는 최소 노드의 개수) |
| R | 읽기 연산에 대한 정족수 (읽기 연산이 성공한 것으로 간주되는 응답을 받아야 하는 최소 노드의 개수) |

**정족수**
- 모임이나 단체에서 어떤 결정을 내릴 수 있는 최소의 인원수. (의사를 진행하고 결정하는 데에 필요한 최소한의 출석 인원)

**정족수 합의 프로토콜**
- 분산 데이터베이스나 분산 시스템에서 여러 노드에 데이터를 복제하여 저장할 때, 데이터의 일관성과 가용성을 보장하기 위해 의사결정에 필요한 최소한의 노드 수(정족수)의 응답을 요구하는 합의 방식

**예시)** W=1 이어도 한대 서버에만 기록되는건 X
s0,s1,s2에 다중화 되는 상황에서 최소 한대 서버로 부터 쓰기 성공 응답을 받아야 한다는 뜻으로 중재자가 클라이언트와 노드 사이에서 프락스 역할을 한다

**프락시**
- 대신하여 무언가를 처리하는 역할

**NWR 시스템 예시 - 요구되는 일관성에 따라 값을 조정**

| 설정 | 특징 |
| --- | --- |
| R=1, W=N | 빠른 읽기 연산에 최적화 시스템 |
| W=1, R=N | 빠른 쓰기 연산에 최적화 시스템 |
| W+R > N | 강한 일관성이 보장됨 (ex. N=3, W=R=2) |
| W+R <= N | 강한 일관성이 보장되지 않음 |

#### 4) 일관성 불일치 해소

**일관성 모델**

| 종류 | 설명 |
| --- | --- |
| 강한 일관성 | 모든 읽기 연산은 가장 최근 갱신 결과를 반환. 낡은 데이터 조회 X |
| 약한 일관성 | 모든 읽기 연산은 최신 결과를 반환 못할수 있다. |
| 결과적 일관성 | 약한 일관성의 하나로, 갱신 결과가 모든 사본에 반영(동기화) |

강한 일관성을 하려면 모든 사본에 현재 쓰기/연산 결과가 반영될때까지 해당 데이터에 대한 읽기/쓰기 금지하면 되지만 고가용성 시스템에는 적합하지 않다.

**개선방법**
- 데이터의 버전정보를 활용해 일관성 깨진 데이터를 읽지 않는 방법

**데이터 버저닝 (비 일관성 해소 기법)**
데이터를 다중화하면 가용성은 높아지지만 사본 간 일관성이 깨질 가능성이 높아진다.

**개선방법**
- 버저닝, 벡터 시계

**버저닝**
- 데이터를 변경할때마다 버전을 새로 만들며 각 버전의 데이터는 변경 불가능

**벡터 시계**
- [서버,버전]의 순서쌍을 데이터에 매달아 버전의 순서를 체크하거나 충돌 여부를 판별. 충돌을 발견하고 자동으로 해결할 버저닝 시스템 중 하나

**장점**
- 어떤 버전이 이전 버전인지 쉽게 판단 가능

**단점**
- 출돌 감지 및 해소 로직이 클라이언트에 들어가 구현이 복잡해짐
- [서버:버전]의 순서쌍 개수가 빨리 늘어나 충돌 해소 과정의 효율성이 낮음
  = 임계치를 설정해 오래된 순서쌍을 벡터시계에서 제거하는데 버전간 선후 관계가 정확하게 결정이 어려워 충돌 해소 과정의 효율성이 낮아짐)

#### 5) 장애 처리
- 시스템에서 장애는 흔하게 벌어지는 일이므로, 장애를 어떻게 처리할 것인가가 중요하다
- 장애 감지 와 장애 해소 전략을 사용해서 장애 처리를 진행

**장애 감지**
- 일반적으로 두대 이상 서버가 장애 발생시 실제로 장애로 간주함.
- 서버 적을경우 : 멀티캐스팅 채널을 구축해 서버 장애를 감지하는게 쉽지만 서버가 많을때는 비효율적이다.
- 서버 많을경우 : 분산형 장애 감지 솔루션 사용 ex) 가십 프로토콜

**가십 프로토콜**
- 분산형 장애 감지 솔루션
- 서버들이 서로 정보를 주고 받으며 전체 서버의 상태를 파악하는 통신
ex)
중앙에서 관리자가 감시 (x) 
서로 장애 여부를 확인 (o)

**가십 프로토콜 동작 원리**
1. 각 노드는 멤버십 목록을 유지
2. 각 노드는 주기적으로 자신의 박동 카운터를 증가
3. 각 노드는 무작위 노드들에게 주기적으로 자기 박동 카운터 목록을 보냄
4. 박동 카운터 목록을 받은 노드는 멤버십 목록을 최신 값으로 갱신
5. 어떤 멤버의 박동 카운터 값이 지정된 시간동안 갱신되지 않으면 해당 멤버는 장애 상태인 것으로 간주

**장애 해소 전략**
- 일시적 장애 처리
- 영구 장애 처리
- 데이터 센터 장애처리

**일시적 장애 처리**
- 느슨한 정족수 접근법 : 가용성을 높여 정족수 요구사항을 강제하는 대신 쓰기/읽기 연산을 수행할 W개/R개의 건강한 서버를 해시링에서 고름
- 임시 위탁 기법 : 조건을 완화하여 네트워크가 장애 서버로 가는 요청을 다른서버가 잠시 맡아 처리하여 데이터 일관성을 보존하는 방식으로 그동안 발생한 변경하상은 해당 서버가 복구되었을때 일괄반영

**영구 장애 처리**
- 반-엔트로피 프로토콜을 구현해 사본들 동기화
- 머클 트리를 사용해 사본간 일관성이 망가진 상태를 탐지하고 전송 데이터의 양을 줄임

**머클 트리 구성 과정**
1. 키 공간을 버킷으로 나누고
2. 버킷에 포함된 각 키에 균등 분포 해시 함수를 적용해 해시 값을 계산
3. 버킷별로 해시 값 계산 후 해당 값을 레이블로 갖는 노드를 만든다
4. 자식노드의 레이블로부터 새로운 해시 값을 계산해, 이진 트리를 상향식으로 구성

**머클 트리 비교**
- 해시 값 비교
- 같으면 같은 데이터 가진것으로 본다.

| 구분 | 머클 트리 | 블룸 필터 |
|---|---|---|
| 목적 | 데이터의 일치 여부 확인 | 데이터의 존재 가능성 확인 |
| 핵심 기술 | 해시 + 트리 | 해시 + 비트 배열 |
| 주요 활용 | 데이터 동기화, 무결성 검사 | 불필요한 DB 조회 방지 |
| 특징 | 서로 다른 데이터 영역을 찾음 | 없다는 것은 확실하게 판단 가능 |

**데이터 센터 장애처리**
- 정전, 네트워크 장애 등 발생할수 있으므로 여러 데이터 센터에 다중화 하자

#### 6) 시스템 아키텍처 다이어그램
- 클라이언트는 키-값 저장소가 제공하는 get, put과 통신
- 중재자는 클라이언트에게 키-값 저장소에 대한 프락시 역할을 하는 노드
- 노드는 안정 해시의 해시 링 위에 분포
- 노드를 자동으로 추가/삭제 가능하게 시스템은 완전히 분산
- 데이터는 여러 노드에 다중화
- 모든 노드가 같은 책임을 지므로 SPOF 는 존재하지 않는다.

**SPOF**
- Single Point of Failure
단일 장애 지점 : 시스템 구성 요소 중에서 단 한 곳에만 문제가 생겨도 전체 시스템이나 서비스가 멈추어 버리는 구조적 취약점

#### 7) 쓰기 경로
쓰기 요청이 특정 노드에 전달될때의 카산드라의 사례 예시로 커밋 로그에 기록, 데이터 메모리 캐시에 기록, 임계치 도달시 디스크 SSTable에 기록 등이 있다

#### 8) 읽기 경로
읽기 요청이 특정 노드에 전달될때의 예시로 데인터가 메모리 캐시에 있는지 확인한다

**데이터 있을경우**
- 클라이언트에 반환

**데이터 없을경우**
- 디스크에서 가져옴. SSTable에 찾는 키가 있는지 체크해야 하는데 블룸 필터를 사용한다.

## 인상 깊은 구절

> (키-값 저장소는 가용성과 일관성) 어떤 두가지를 충족하려면 나머지 하나는 반드시 희생되어야 한다는 것을 의미한다. / 파티션 문제가 발생하면 우리는 일관성과 가용성 사이에서 하나를 선택해야 한다. / 시스템에서 장애는 불가피 한 것이 아니라 아주 흔하게 벌어지는 사건이다.
> — p.93, p.95, p.105

**왜 인상 깊었나:**
시스템적으로 장애는 불가피한 것으로 어떻게 장애를 해결할 것인지 중요하다고 말하는 것에서 다른 관점에서 바라보게 되는데..
CAP 정리를 예시를 들면, 모든 요구사항을 완벽하게 만족하는 시스템을 만드는 것이 아니라 서비스의 특성에 따라 일관성과 가용성 사이에서 선택하여 선택해야 하는 상황이 발생하는데
완벽한 시스템을 충족시키긴 어려우니 선택을 하지만 그로 인해 다른 문제가 발생할수도 있기에 이 기준을 어떻게 우선할지 판단하는 것이 이번 내용에서 가장 중요한 부분으로 생각해서 선정하였음.

## 면접 예상 질문
1. **Q. CAP 정리란 무엇인가요?**
   **A.** 분산 시스템에서 일관성, 가용성, 파티션 감내 3가지 요구사항을 만족하는 설계는 불가능하다. 일반적으로 네트워크 장애는 피할수 없으므로 일관성과 가용성 중에서 어느 것을 만족할 건지를 선택하면 된다.

2. **Q. 분산 키-값 저장소에서 안정 해시를 사용하는 이유는 무엇인가요?**
   **A.** 서버가 추가/삭제시 데이터의 이동을 최소화 하기 위해 재배치를 하며 데이터를 여러 서버에 고르게 분산 할수 있다. (가상 노드를 활용)

3. **Q. 가십 프로토콜은 무엇인가요?**
   **A.** 분산형 장애 감지 솔루션으로, 서버들이 서로 정보를 주고 받으며 전체 서버의 상태를 파악하는 통신 방식이다. 예로 들어 중앙에서 관리자가 감시를 하는게 아니라 서로 장애 여부를 확인하는 것으로 보면 된다.

4. **Q. 머클 트리와 블룸 필터의 차이점은 무엇인가요?**
   **A.** 머클 트리는 서버 간 데이터가 같은지 비교하고 다른 부분을 찾는 데 사용하지만 불룸 필터는 특정 데이터가 존재하는지 빠르게 확인하는데 사용한다.
