## 어디서 막혔나

책 1장은 비관계형 데이터베이스가 바람직한 경우로 "아주 낮은 응답 지연시간이 요구됨", "다루는 데이터가 비정형", "데이터를 직렬화·역직렬화할 수만 있으면 됨", "아주 많은 양의 데이터를 저장할 필요가 있음"을 든다.

마지막 조건이 납득되지 않았다. 관계형 데이터베이스는 스키마로 형식이 정해져 있으니 오히려 더 많은 양의 데이터를 효율적으로 저장할 수 있을 것 같았다. 책은 NoSQL이 왜 대용량에 유리한지 이유를 설명하지 않는다.

## 어떻게 물었나

1. 장 노트의 "더 알아볼 것"에 적어 둔 질문을 그대로 던졌다. "왜 비관계형 데이터베이스가 아주 많은 양의 데이터를 저장할 때 바람직한 선택인가? 느낌상 관계형 데이터베이스가 형식이 정해져 있어 더 많이 저장할 수 있을 것 같다."
2. 내 추측을 함께 적은 것이 효과가 있었다. 답이 일반론에서 끝나지 않고, 내 추측의 어디가 틀렸는지부터 짚어 줬다.
3. 이어서 NoSQL 4가지 분류(키-값, 문서, 칼럼, 그래프)의 특징도 물었다.

## 무엇이 풀렸나

**내 추측이 틀린 지점**: 문제는 "얼마나 많이 저장하나"가 아니라 "한 대에 다 안 들어갈 때 여러 대로 어떻게 나누나"다. 서버 한 대의 디스크 용량은 RDB든 NoSQL이든 똑같이 한계가 있다. 데이터가 그 한계를 넘으면 여러 서버로 나눠야(수평 확장) 하고, 이 나누기가 어느 쪽이 쉬운지가 갈린다.

**RDB가 나누기 어려운 이유**
- 조인: 서로 관계된 테이블이 다른 서버에 흩어지면, 조인할 때마다 네트워크를 넘어 데이터를 모아야 해서 느려진다.
- 트랜잭션: 여러 서버에 걸친 데이터를 하나의 트랜잭션으로 묶으려면 분산 트랜잭션이 필요하고, 비용이 크고 복잡하다.
- 외래키 같은 제약 조건도 서버가 나뉘면 지키기 어렵다.
- RDB도 샤딩은 할 수 있다. 다만 위 기능을 일부 포기하거나 애플리케이션이 대신 처리해야 해서 부담이 크다.

**NoSQL이 나누기 쉬운 이유**
- 처음부터 키 단위로 데이터를 분산하도록 설계됐다. 필요한 데이터를 한 문서나 한 키에 몰아 담아(비정규화), 조회가 서버 한 대 안에서 끝난다.
- 키를 해시해서 어느 서버에 둘지 정하므로, 서버를 추가하면 데이터 일부만 옮기면 된다. 이 내용은 5장 안정 해시와 이어진다.

**대가**
- 조인이 없으니 데이터를 중복 저장하거나 애플리케이션에서 합쳐야 한다.
- 성능과 가용성을 위해 강한 일관성 대신 최종 일관성(eventual consistency)을 택하는 경우가 많다. 이 내용은 6장 키-값 저장소의 CAP 정리와 이어진다.

**NoSQL 4가지 분류**

| 분류 | 저장 방식 | 강점 | 예시 |
| --- | --- | --- | --- |
| 키-값 저장소 | 키 하나에 값 하나 | 단순하고 매우 빠르다. 캐시, 세션 저장소 | Redis, DynamoDB |
| 문서 저장소 | JSON 같은 문서 단위 | 스키마가 유연하다 | MongoDB |
| 칼럼 저장소 | 칼럼(열) 단위 묶음 | 대량 쓰기와 분석에 강하다 | Cassandra, HBase |
| 그래프 저장소 | 노드와 관계(엣지) | 관계 탐색에 강하다. 추천, SNS | Neo4j |

**결론**: "RDB는 형식이 정해져 있어 많이 저장한다"가 아니라, "RDB는 관계와 일관성을 지키느라 여러 서버로 나누기 어렵고, NoSQL은 그걸 일부 포기하는 대신 나누기 쉽다"다.

## AI가 틀린 것

아직 검증 전이다. 검증한 뒤 채운다.

다음 부분은 단순화된 설명일 수 있어 따로 확인할 것.

| AI의 답 | 확인할 점 |
| --- | --- |
| NoSQL은 강한 일관성 대신 최종 일관성을 택한다 | 모든 NoSQL이 그렇지는 않다. MongoDB, DynamoDB는 강한 일관성 읽기 옵션도 제공한다. 어느 정도까지 일반화할 수 있는지 확인 필요 |
| RDB는 수평 확장이 어렵다 | Vitess(MySQL), Citus(PostgreSQL)처럼 RDB를 샤딩해 주는 도구도 있다. "불가능"이 아니라 "비용이 크다"로 이해해야 한다 |

## 다음에 물을 때

- 질문에 내 추측을 함께 적는다. AI가 일반론 대신 내 오해 지점부터 짚어 준다.
- "왜 X가 더 좋은가"보다 "Y에서는 X가 구체적으로 왜 어려운가"처럼 메커니즘을 묻는다.
- 답에 "항상", "모든" 같은 일반화가 나오면 반례가 있는지 다시 묻는다.
- 책의 뒷 장(5장 안정 해시, 6장 키-값 저장소)과 연결되는지 물어서 앞으로 읽을 내용과 이어 둔다.
